🚨 V2 新发现问题（20 项）

P0 1. CSS 语法错误 — 第 1159 行多余闭合括号
.tag-ai-generated 规则块结束后存在一个孤立的 }（第 1159 行），导致后续的 .note-detail-empty 等规则被浏览器错误解析为嵌套规则，在部分浏览器中样式失效。这是发布阻断级缺陷。
修复：删除第 1159 行的多余 }，用 CSS Validator 验证全文件无语法错误。
P0 2. XSS 漏洞 — innerHTML 拼接未转义用户数据
renderDetailContent() 函数直接将 entry.content、entry.title、entry.summary 通过 innerHTML 注入 DOM，未做任何 HTML 转义。若 data.json 被篡改或数据库写入未消毒，攻击者可注入任意脚本。500 万项目存在 XSS 漏洞是不可接受的合规风险。
修复：添加 escapeHtml() 工具函数，对所有动态文本内容进行转义后再拼接。或改用 textContent + DOM API 构建元素。
P0 3. SECRET_KEY 硬编码 — 专属页面密钥客户端暴露
const SECRET_KEY = '4b68ab3847feda7d' 写在 script.js 第 11 行，任何人查看源码即可访问"X 访客专属页面"。这使所谓的"专属"形同虚设。库洛/网易的专属内容均通过服务端鉴权实现。
修复：将页面路由判断移至服务端（如 Cloudflare Workers / GitHub Actions 构建时生成不同版本），或使用 JWT token + 服务端验证。客户端不得存储任何密钥。
P0 4. data.json Email 链接缺少 mailto: 前缀
data.json 第 92 行 Email 的 url 为 "1447954419@qq.com"，缺少 mailto: 前缀。点击后会尝试导航到该字符串作为 URL，导致 404 或错误页面。而 index.html 中硬编码的 Email 链接（第 139 行）是正确的 mailto:，说明数据与模板不一致。
修复：将 data.json 中 Email url 改为 "mailto:1447954419@qq.com"。
P0 5. 无首屏加载序列 — 500 万项目无 cinematic 体验
页面打开后直接渲染内容，骨架屏虽然存在但无过渡编排。库洛的鸣潮有粒子聚合 → logo 浮现 → 内容展开的三段式加载；网易阴阳师有卷轴展开 + 樱花飘落入场。当前版本的首屏体验是"打开即看到"，缺少品牌仪式感，在 PK 评审中会被直接淘汰。
方案：设计 1.5-2s 的首屏序列：① 背景渐变淡入(0.3s) → ② 粒子从中心向外扩散(0.5s) → ③ 头像光圈展开(0.4s) → ④ 卡片 stagger 入场(0.6s)。使用 CSS animation-delay 编排时序，确保总时长 ≤ 2s 避免用户流失。
P0 6. 无品牌识别系统 — emoji 图标无法与竞品竞争
所有 section 标题使用 emoji（🌸🌿📝💌🚀💭⚡🔗）作为图标，Projects 和 Life Cards 也用 emoji（🤖📖🌟🧪📷🎵🐱☕）作为主视觉。这是业余设计的标志性特征。库洛有完整的自研 UI 图标库（200+ 图标），网易阴阳师有全套和风SVG 插画。500 万预算的交付物使用 emoji 作为核心视觉元素，在 PK 评审中会被直接扣分。
方案：委托视觉设计师制作 20-30 个品牌专属 SVG 图标（猫系/治愈/数字花园主题），统一线宽 2px、圆角风格。同时设计 1 张 hero 区域主视觉插画（如猫耳少年坐在数字花园中的场景图）。
P1 7. 无声效设计 — 顶级体验需要 micro-audio
页面无任何音效反馈。日历切换、卡片 hover、链接点击等交互均为静默。库洛/网易的旗舰产品均有精细的 UI 音效设计（风铃声、水墨声、按键音等），是营造沉浸感的关键要素。
方案：引入 Web Audio API，为关键交互设计 3-5 个短促音效（≤0.3s）：hover 轻柔风铃、click 水滴、toggle 猫叫。提供静音开关并尊重用户偏好。
P1 8. 无动效编排系统 — 动画各自为战
当前有 stagger 入场、hover 反馈、粒子系统、视差跟随等动画，但它们是独立运行、无时序协调的。顶级产品的动效有明确的"信号灯"编排：先背景 → 再容器 → 最后内容，形成视觉叙事。当前版本缺少这种 choreography 层面的设计。
方案：定义动效编排协议：① 场景级（页面切换 0.5s）→ ② 容器级（卡片入场 0.06s stagger）→ ③ 元素级（hover 0.25s）。使用 CSS animation-delay 和 JS 时序控制实现分层编排。
P1 9. 日历事件监听器内存泄漏
bindCalendarEvents() 在每次月份切换/重渲染时被调用，通过 addEventListener 绑定新的点击事件，但未清理旧的监听器。用户切换 10 次月份后，每个日期按钮上会累积 10 个 click 监听器，导致内存增长和重复触发。
修复：使用事件委托（在 container 上绑定一次性 listener），或在重渲染前 removeEventListener 清理旧监听器。
P1 10. 无性能预算与监控
500 万项目无 Lighthouse 目标分数、无 Core Web Vitals 阈值、无性能监控埋点。库洛/网易均有明确的性能预算（如 LCP ≤ 2.5s, CLS ≤ 0.1, INP ≤ 200ms）和自动化性能回归检测。
方案：① 定义性能预算：LCP ≤ 2s, CLS ≤ 0.05, INP ≤ 150ms, TBT ≤ 200ms ② 集成 Lighthouse CI 到 GitHub Actions ③ 接入 web-vitals 库上报真实用户数据。
P1 11. 无结构化数据 / sitemap / robots.txt
虽然有 OG 标签，但缺少 JSON-LD 结构化数据（Person、WebSite schema）、sitemap.xml 和 robots.txt。搜索引擎无法正确理解页面内容，影响 SEO 效果。
修复：① 添加 Person schema JSON-LD ② 生成 sitemap.xml ③ 创建 robots.txt ④ 添加 canonical URL。
P1 12. 无 skip-to-content 跳转链接
键盘用户每次页面加载后需要 Tab 遍历所有导航元素才能到达主内容区。WCAG 2.1 SC 2.4.1 要求提供跳转机制。当前版本无 skip link，可访问性不完整。
修复：在 <body> 首个元素添加 <a href="#main-content" class="skip-link">跳到主内容</a>，默认视觉隐藏，focus 时显示。
P1 13. 日历无键盘方向键导航
日历日期格子虽然改用了 <button>，但无法通过方向键（←→↑↓）在日期间导航。WCAG 2.1 SC 2.1.1 要求所有功能可通过键盘操作。库洛/网易的日历组件均支持完整的键盘网格导航。
修复：为日历网格添加 keydown 事件监听，方向键移动选中日期，Enter 确认选择。添加 role="grid"、role="gridcell" 和 aria-selected。
P1 14. data.json 遗留 Font Awesome icon_class 字段
data.json links 数组中每个条目仍保留 "icon_class": "fa-brands fa-x-twitter" 等 Font Awesome 类名，但前端已改用内联 SVG。这些字段是死代码，增加数据体积且容易引起维护混乱。
修复：清理 data.json 中所有 icon_class 字段，或在 renderLinks() 中移除对该字段的引用。
P1 15. 暗色模式桌面端仍保留 backdrop-filter blur(28px)
暗色模式 CSS（第 1437 行）为主卡片重新启用了 backdrop-filter: blur(var(--glass-blur))，而 --glass-blur 为 28px。在暗色背景下，高强度模糊的性能开销更大（GPU 合成层更重）。移动端虽然禁用了 blur，但桌面端暗色模式下的性能未做优化。
修复：暗色模式下将 --glass-blur 降至 16px，或使用不透明背景 + 微妙渐变模拟玻璃感，避免真实模糊计算。
P1 16. 无错误边界 — 数据加载失败静默降级
loadData() 的 catch 分支使用 console.warn 静默降级到默认数据，用户无任何感知。若 data.json 加载失败，用户看到的是过时的默认数据而非错误提示，可能产生困惑。500 万项目应具备完善的错误处理和用户反馈机制。
修复：添加用户可见的错误状态 UI（如 toast 通知"数据加载失败，显示缓存数据"），并接入错误上报（Sentry / 自建埋点）。
P2 17. og:image 未做社交卡片专属设计
OG image 指向 pics/SH.JPG（头像照片），未按 1200×630 社交卡片标准设计。在微信/Twitter 分享时显示效果不佳，缺少品牌信息和网站标题。库洛/网易的社交卡片均有专属设计。
方案：设计 1200×630 的社交分享卡片（含网站标题、品牌色背景、装饰元素、头像），导出为优化后的 JPG/WebP。
P2 18. manifest.json 图标尺寸不完整
manifest.json 仅提供 192×192 和 512×512 两个尺寸，且都指向同一个 favicon.png。缺少 32/72/96/128/144/256/384 等中间尺寸，且未提供 maskable 图标的安全区域设计。PWA 安装在不同设备上图标显示效果不理想。
修复：生成完整尺寸图标集，或使用 SVG 图标 + purpose: "any maskable"。
P2 19. 无 print 样式 + 无 prefers-contrast 支持
缺少 @media print 打印样式（用户打印页面时背景装饰浪费墨水、布局混乱）。同时缺少 @media (prefers-contrast: high) 高对比度模式支持。
修复：添加 print 样式（隐藏装饰层、调整文字为黑色白底），添加高对比度模式覆盖。
P2 20. CSS contain 属性缺失 + 重复代码
未使用 CSS contain 属性隔离渲染树，背景动画和粒子系统可能触发不必要的布局重计算。同时移动端 media query 中重复设置 background 和 backdrop-filter: none（已在主规则中设置），代码冗余。
修复：为 .card、.calendar-wrapper 等容器添加 contain: layout style paint；清理重复的 media query 声明。

评审结论

前端工程师在 V1→V2 周期内展现了极强的执行力，17 项问题修复了 15 项，代码质量和工程规范显著提升。但以 500 万预算对标库洛/网易的 PK 标准衡量，当前版本的核心差距不在"技术实现"而在"设计深度"和"品牌投入"。

竞品在品牌识别系统、自定义插画、首屏仪式感、声效设计四个维度建立了代差级优势，这些不是前端工程师能独立解决的——需要视觉设计师、动效设计师、音效设计师协同介入。

建议：阶段 1 立即执行（3 天内），阶段 2 启动跨职能协作（1-2 周），阶段 3-4 按计划推进。在 PK 评审前至少完成阶段 1-2，方可具备基础竞争力。
